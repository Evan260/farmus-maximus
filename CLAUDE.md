# Farmus Maximus: Claude Code Guide

A cozy semi-idle Roman lavender-farming game for Steam (Windows, Mac, Linux, Steam Deck), with a full-window mode and a desktop idle strip. Claude writes the code and generates the art; the user tests, gives feedback, adds music and sound effects, and handles marketing.

## Fixed decisions

- Base scene 480 x 270 pixels. The estate is drawn in its own viewport (`main.gd`, class `Estate`), scaled by the largest whole number that shows the full height (a tall narrow window crops the sides instead, down to 300 pixels across), and sized to fill the window, so there are never black bars. `main.gd` builds the scene and handles input; its parts live in `scripts/estate/`: `cart_rig.gd` (the donkey and cart), `road_works.gd` (paving, kerb, milestones, footpath, stone cart), `villa_view.gd` (the farmhouse, its scaffold, lit windows and wreath), and `scenery.gd` (grass, weeds, flowers, overgrowth); the demo and maxed farms and the windows opened from the command line are the `Dev` autoload's, which the estate sets itself on as `Dev.m`. Each is a child node with `m`, the estate scene, to work on. The sky is drawn behind it at screen resolution so clouds and the moon glide; the interface is drawn over it at its own whole-number scale (`Windowing.scale`, `Windowing.ui_scale`).
- All game data (crops, prices, timings, upgrades) lives in data files, never hard-coded.
- Art: one cohesive background painting per land; nothing that moves inside a background; everything that moves or changes is a separate sprite; buildings sit on fixed anchor spots with one sprite per stage.
- Characters are generated outline-free with natural proportions to match the backgrounds.
- No punishment for being away: crops never die; the only offline limit is a full storehouse and parked cart. A parked cart adds its space to the storehouse's (`Game.holding_capacity()`), because it is drawn loaded with the goods waiting for market; while it is on the road only the storehouse holds anything.
- Saves: a player keeps up to three farms, each in `user://farm_<n>.json` with three rolling backups; `user://farms.json` remembers the one played last (`save_service.gd`). The farm's name and whether it has had its first-day welcome are part of each save. The house button at the top right saves and shows the title again, where the farm list switches farms; a farm is never started over another, so with three farms New farm waits until one is deleted.
- Settings, the volumes and the strip's own settings are one `user://settings.cfg` (`Settings.cfg`, written through `Settings.save()` and `Settings.store()`); the first start after the change carries over the three JSON files they were kept in before.
- Sounds are found by file name: `Audio.play("rain")` plays `assets/audio/sfx/rain.wav` if it exists and is silent otherwise; any file in `assets/audio/music/` joins the playlist, as does any in the player's own `user://music/` folder, which Settings > Sound opens. `docs/Sound-list.md` lists the names the game asks for.
- The demo is the same project exported with the `demo` feature (presets in `game/export_presets.cfg`); `Game.is_demo()` caps it at villa stage 3 and the first two zones.

## Running and checking

- Tests: `Godot_..._console.exe --headless --path game -- --run-tests` must print `ALL TESTS PASSED`; `--only=NAME` runs the test files whose names contain NAME. Each file in `tests/` named `test_*.gd` extends `test_case.gd`, and each of its `test_` methods is run by `run_tests.gd`. A test that raises an error fails, unless its file sets `EXPECTS_ERRORS` for the engine errors it causes on purpose; a script error always fails. `test_translations.gd` checks every shown string is in the sheet in all 14 languages with its placeholders, and that the fonts draw every letter.
- Pacing: `--headless --path game -- --pacing --hours=40` plays the estate as a keen player and prints when each milestone arrives; run it after any balance change. `--completion` (same arguments) plays on towards 100%, buying every building level and decoration, and prints when each achievement unlocks and what is still missing. `tests/check_real_save.gd` loads the real save into the current rules without writing anything.
- Exact screenshots: `Godot_..._console.exe --path game --quit-after 600 -- --demo-state --shot=OUT.png --quit` (`--shot-at=SECONDS`, 0.75 by default; `--quit` closes the game after the last picture), plus `--strip`, `--strip --solid`, `--hour=22.5`, `--villa=2`, `--send-cart`, `--estate` (every zone, building, helper and decoration in use), `--zone=pasture`, `--weather=rain`, `--day=12` (winter), `--town` (the market screen), `--window=1420x710` (any window size), `--panel=journal` (or `helpers`, `store`, `settings`, `upgrades`, a building id such as `cellar`, `farms` for the title's farm list, or `delete` for the first farm waiting for "delete" to be typed, which never deletes it). `--town=Shop` opens a place in the market, `--burst=PREFIX` saves `PREFIX_00.png` and on over time for checking motion and flicker (`--burst-start`, `--burst-gap`, `--burst-count`; eight frames a quarter of a second apart by default), `--hover=X,Y` and `--click=X,Y` point and click in interface pixels (at `--hover-at` and `--click-at` seconds, as for showing a tip), `--ui-size=N` tries an interface size from -1 (Smaller) to 2 (Largest), `--screen=town`, `inside` or `title` opens that screen, `--no-save` writes nothing anywhere, settings included, `--readonly` loads the real save without ever writing it, and `--new-farm` starts a fresh farm with the first-day welcome and saves nothing. `--cart=3` shows the cart at that upgrade level, `--road=2` paves the road that far, `--start=channels` (or `storage`, `cart_speed`) starts that farm improvement, `--build-villa` starts the next farmhouse stage, and `--rainbow` puts a rainbow in the sky. `--inside` opens the farmhouse interior (use `--villa=3` or more for the restored room; `--inside=list` or `--inside=lamps` also opens the furnishing window), `--furnish=all` (or `--furnish=fire,lamps`) has those furnishings bought, `--window=` always opens the full window even if the player left the game as the strip. `--debug-panel` opens the F1 debug panel, `--galaxy` shows the Milky Way tonight (with `--hour=0.5 --weather=sun`); it otherwise comes on about half of the clear nights near the new moon, never on a night of northern lights. `--max-state` (the "maxed farm" launcher, and `Farmus Maximus - everything unlocked.bat` beside an exported game) has everything finished and at its top level. Neither touches the real save; `--demo` and `--demo --maxed` are their older names, which the trailer and store tools still use. `--aurora` brings out the northern lights tonight (with `--hour=23 --weather=sun`; `--aurora=vertical` or `--aurora=horizontal` picks the night's shape, which is otherwise chosen at random each night), `--title` shows the title screen, which otherwise only opens on a launch with no flags, `--triumph` grants every achievement but the last so the Triumph celebration plays, `--achievement` slides in the cards for the next two achievements not yet earned (or `--achievement=excellent,sell_100` for those), `--greet` makes every person on screen greet at once (the first in view also says something in a speech bubble), `--guide` shows Uncle Marcus's advice from the first step (or `--guide=cart` from a later one), `--pets=lapdog,longhair` sets the dog's and cat's breeds (`--pets=lapdog:apricot` also the dog's coat), `--panel=settings:Display` opens a settings tab, `--panel=journal:animal:bees` opens a journal entry, and `--panel=turn:Goods` opens the journal and turns its page to that section (with `--burst` to watch the leaf turn; the turn itself is `scripts/ui/page_turn.gd`, shared with Fishus Maximus).
- Benchmark: `bash tools/bench.sh OUT.jsonl 20` runs the game windowed at 1440x810 on the maxed farm for 20 seconds in each heavy scene (`estate`, panned end to end; `night`, with the northern lights; `rain`; `town`; `inside`, fully furnished; `journal`, turning a page every 1.5 seconds; `strip`) and appends one line of JSON per scene to OUT.jsonl: frames per second, the average and slowest 1% frame time with the frame rate uncapped, the time the scripts take each frame, draw calls, visible canvas items, objects, nodes, orphan nodes, and static and texture memory. Name scenes after the seconds to run only those, such as `bash tools/bench.sh OUT.jsonl 10 town inside`. It is `game/tools/bench.gd`, started by `--bench=NAME`; `--bench-skip=NAME` stops every node whose script path contains NAME from processing, to see what those scripts cost.
- After adding or changing any picture or sound, run `Godot_..._console.exe --headless --path game --import`. The game only reads its imported copies, so without this it keeps showing the old file.
- Always wrap capture runs in `timeout 60` and pass `--quit-after`: a script error stops the scene before it can quit, and the window then waits forever.
- Play-test build: `Godot_..._console.exe --headless --path game --export-release "Windows" "../builds/windows/Farmus Maximus.exe"` makes one self-contained .exe (export templates for 4.7.2 are installed in `%APPDATA%\Godot\export_templates`). Both Windows presets use the trimmed engine in `tools/engine/bin/` (about 33 MB instead of 105 MB, git-ignored), built by `python tools/engine/build_template.py` from the Godot source; rebuild it after a Godot update or on a new computer, or the Windows export fails. The Mac and Linux presets use the stock templates. Write `Credits and licences.txt` beside it with `--headless --path game --script res://tools/write_credits.gd -- --out=PATH` (Godot's licence and the stork recording's CC BY licence ask to ship with the game; `publish.py` does this for Steam builds), and zip both with `tools/playtest/How to play test.txt` to send to a tester; `builds/` is git-ignored. The F1 debug panel only opens in development builds.
- The movie writer (`--write-movie`) always records at 480x270, so it cannot show the desktop strip's real shape; use `--shot` for that.
